# 要件定義書：行きたい場所リスト（仮）

> アプリ名は仮です。決まりしだい直します。

## 1. プロジェクト概要

- 背景: 行ってみたいお店・公園・観光地などを SNS やメモ、地図アプリのあちこちに残していて、行こうとしたときに見つからない。家族それぞれが別々に覚えているので、「あそこ行きたいって言ってたよね」が共有できない。いつ行くかを決めた場所も、カレンダーとは別に覚えておく必要がある。
- 目的: 家族の行きたい場所を 1 か所にまとめ、カテゴリで探せて、日程を決めた場所は家族の誰でもすぐに分かる状態にする。
- スコープ:
  - 含むもの: 場所の登録・編集・削除、カテゴリ分け、日程の登録、行った記録、合言葉による利用の制限、自分と家族での共有
  - 含まないもの: アカウントの作成・ログイン、家族以外の人の利用、複数の家族での利用、お店の予約、地図上での検索、通知、ネイティブアプリ（スマホはブラウザで使う）

## 2. ユーザーストーリー

As a 行きたい場所を集めている家族の一員,
I want 見つけた場所を URL やメモと一緒にすぐ登録できること,
So that あとで行こうとしたときに探し回らずに済む.

As a 家族の一員,
I want 家族が登録した場所も同じリストで見られること,
So that 家族それぞれの行きたい場所を知り、一緒に行く場所を決められる.

As a 家族の一員,
I want 場所をカテゴリ（ごはん・カフェ・公園・観光など）別に見られること,
So that その日の気分や目的に合う場所をすぐ選べる.

As a 家族の一員,
I want 行く日を決めた場所を日付順にまとめて見られること,
So that 家族の誰もが予定を忘れず、直前に場所の情報を確かめられる.

As a 家族の一員,
I want 行った場所に「行った」と印を付けられること,
So that まだ行っていない場所と区別できる.

As a 家族の一員,
I want アカウントを作らずに合言葉だけで使い始められること,
So that 家族に URL と合言葉を伝えるだけで共有できる.

## 4. 非機能要件

- パフォーマンス: ページ読み込み 3 秒以内（スマホの 4G 回線で）
- セキュリティ:
  - アカウントは作らず、家族で共通の合言葉 1 つで利用を制限する。合言葉は Vercel の環境変数（`APP_PASSWORD`）に置き、コードや Git には含めない
  - 合言葉が合っていたら、署名付きの Cookie（HttpOnly・Secure）を発行し、有効期限（例: 1 年）まで合言葉を聞かない。合言葉を変えると、それまでの Cookie は使えなくなる
  - Supabase にはサーバー側（Next.js の Server Actions / Route Handlers）からだけ接続し、`service_role` キーはブラウザに渡さない。テーブルは RLS をオンにしてポリシーを作らず、ブラウザ用の `anon` キーからは読み書きできないようにする
  - 合言葉は iPhone のパスワード欄でも入力できるよう、半角英数字にする
- データの整合性: 家族が同時に同じ場所を編集したときは、後から保存した内容で上書きする（MVP では競合の検出はしない）
- 可用性: SLA 99%（目標）。無料プランには SLA の保証がなく、Supabase の無料プランは 1 週間アクセスがないとプロジェクトが一時停止するため、実際は保証できない
- スケーラビリティ: 利用者は自分と家族の数人。同時接続は 10 ユーザー程度を想定する
- 使いやすさ: スマホの画面幅で使えること（レスポンシブ）

## 5. 制約条件

- 予算: 無料枠で完結（クレジットカードの登録が要らないプランを使う）
- 期間: 2 週間
- 技術: Next.js + Supabase + Vercel

## 6. 画面遷移

```
合言葉の入力（初回だけ）
└── 名前の選択（初回だけ）
    └── トップページ
        ├── リスト一覧
        │   ├── 場所の詳細
        │   └── カテゴリ別
        └── 日程を決めたもの
            └── 場所の詳細
```

- 登録・編集の画面は、リスト一覧と場所の詳細から開く（図には含めていない）
- 合言葉の Cookie がないときは、どの画面からも合言葉の入力へ移る
